# Approval and evidence

## Safe by default

- Record a redacted finding inline or in an already authorized private ledger.
- Inspect the exact in-scope artifact for repetition of a value already observed, without printing it.
- Draft mitigations, tests, documentation, or a case study locally.
- Verify configuration and public metadata with read-only checks.

## Require action-specific approval

- Delete, rewrite, or force-push history.
- Rotate a secret or recovery method.
- Change an account email, visibility, handle, profile, or authentication setting.
- Contact a maintainer, host, employer, data provider, or other third party.
- Publish a report, case study, screenshot, log, dataset, or code repository.
- Run a broad search across accounts, breaches, people-search services, or unrelated repositories.

A standing authorization for one private ledger permits only privacy-safe records there. It does not authorize remediation or publication.

## Evidence rules

- Prefer “matched in multiple public commits” to an address.
- Prefer a repository URL plus affected commit count to copied commit metadata.
- Prefer a checksum and zero-match audit to an attached raw diagnostic archive.
- Preserve a private locator only when needed to correct the source.
- Record uncertainty explicitly: observed, inferred, unverified, or resolved.
- A mitigation is complete only when a fresh read-only check confirms the intended public surface.
